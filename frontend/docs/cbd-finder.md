# 아파트 밀도 CBD 탐색기 (CBD Finder)

## 한 줄 소개
지역을 지정하면 아파트가 지역 평균보다 두드러지게 밀집한 권역을 자동으로 찾아 **CBD(중심 권역)와 부도심**으로 선정하고, 지도·차트로 보여 주는 웹 기반 도시 공간분석 대시보드.

## 3줄 소개
- 검색 · 지도 클릭 · 영역 직접 그리기로 분석 대상 지역을 지정하면, OpenStreetMap의 아파트 건물을 수집해 육각 격자 밀도를 계산한다.
- 격자 밀도를 지역 평균으로 나눈 **지역대비 밀도(LQ)** 가 임계값을 넘는 격자를 군집화해 규모가 가장 큰 군집을 CBD, 다음 군집들을 부도심으로 선정한다.
- 임계값·격자 크기·평활화·가중치를 바꾸면 데이터를 다시 받지 않고 즉시 재계산되며, CBD 반경별 건물 용도 구성과 행정동 밀도 비교까지 함께 제공한다.

## 문제 정의
"도시의 중심은 어디인가"를 판단할 때 기존 통계는 행정동 단위로 끊겨 실제 밀집 권역의 모양을 보여 주지 못한다.
이 프로젝트는 행정 경계가 아니라 **건물 단위 데이터를 격자로 재집계**해, 경계에 얽매이지 않은 밀집 권역을 사용자가 직접 파라미터를 조정하며 탐색할 수 있게 만든 도구다.

## 분석 방법 (핵심 로직)
| 단계 | 내용 |
|---|---|
| 1. 지역 지정 | Nominatim 검색 / 지도 클릭 역지오코딩(시·도 · 시·군·구 · 읍·면·동) / 다각형 직접 그리기 |
| 2. 아파트 수집 | Overpass API로 `building=apartments`를 받아 영역 폴리곤 내부만 선별 |
| 3. 격자 밀도 | Turf.js 육각 격자로 분할, 가우시안 커널(대역폭 = 격자변 × 계수)로 밀도 평활화 |
| 4. 지역대비 밀도(LQ) | `격자 밀도 ÷ 지역 평균 밀도` — LQ 2.0 = 지역 평균의 2배 |
| 5. 군집화 | 임계값 이상 격자를 Union-Find로 인접 결합, 공간 해시로 근접 탐색 최적화 |
| 6. 선정 | 규모(밀도×면적 합)가 최대인 군집 = CBD, 이하 상위 군집 = 부도심(최대 5개) |

가중치는 **건물 동수**와 **연면적 추정**(외곽 사각형 면적 × 0.75 × 층수) 두 가지 중 선택할 수 있다.

## 주요 기능
- **3가지 지역 지정 방식** — 검색 · 지도 클릭 선택 · 영역 직접 그리기(Esc 취소, 더블클릭 완료)
- **실시간 재계산** — 임계값 / 격자 크기 / 평활화 강도 / 가중치 조정 시 네트워크 재요청 없이 즉시 반영
- **지도 레이어** — LQ 단계별 육각 격자, CBD·부도심 외곽선, 아파트 포인트, 행정동 밀도 채색, 건물 유형별 표시
- **건물 유형 구성** — CBD 중심 반경 1·2·3·5 km 내 전체 건물을 주거/상업·업무/공공·교육/종교·문화/공업/미분류로 분류해 도넛 차트로 제시
- **행정동 비교(SGIS 연동)** — 주택총조사 아파트 수 기반 행정동별 지역대비 밀도 차트·표·지도 레이어
- **자체 제작 SVG 차트** — 히스토그램 · 군집 막대 · 행정동 막대 · 도넛 차트를 차트 라이브러리 없이 직접 구현
- **컨트롤 도움말 팝오버** — 임계값·격자·평활화·가중치의 의미를 실제 데이터로 그린 미니 도식으로 설명
- **한국어/영어 전환 + 라이트/다크 테마** — 사전 기반 i18n(약 700줄), 지도 색상은 UI 테마가 아닌 지도 바탕색을 따르도록 분리

## 기술적으로 공들인 부분
- **공용 Overpass 서버 대응** — `overpass-api.de`는 슬롯이 비어도 요청의 절반가량을 504로 거절하는 것을 실측 확인해, 응답이 안정적인 미러를 기본값으로 전환. 실패 시 엔드포인트 폴백 → 슬롯 대기 → 재시도 순으로 복구하고, 최근 6건 결과를 캐시해 동일 지역 재분석 시 공용 서버에 재요청하지 않음.
- **대용량 공간 연산 최적화** — 건물–격자 매칭과 커널 합산에 공간 해시 버킷을 사용해 O(N×M) 전수 비교를 제거. 격자 수가 7,000개를 넘으면 격자 크기를 자동 확대, 2,500 km² 초과 영역은 사전 차단.
- **좌표계 처리** — SGIS가 UTM-K로 내려주는 행정동 경계를 proj4js로 브라우저에서 WGS84로 변환해 사용.
- **API 이용 정책 준수** — Nominatim 초당 1회 제한을 지키는 요청 큐, 키는 서버 없이 브라우저 localStorage에만 저장.
- **무빌드 구조** — 번들러·프레임워크 없이 HTML/CSS/JS 4개 파일로 동작하며, PowerShell만으로 뜨는 정적 서버 스크립트를 동봉(Python·Node 불필요).
- **접근성/반응형** — `prefers-reduced-motion`, `prefers-color-scheme` 대응, ARIA 속성, 960/620px 브레이크포인트.

## 한계 및 유의점 (정직하게 기재)
- 여기서의 CBD는 전통적 업무지구가 아니라 **아파트 밀집 핵심 권역**을 뜻한다.
- OSM 건물 입력이 부족한 지역은 결과가 치우칠 수 있어 SGIS 통계와 병행 해석이 필요하다.
- 한국 OSM은 `building=yes`만 입력된 건물이 많아 용도 도넛의 미분류 비중이 크게 나올 수 있다.
- 연면적은 응답 경량화를 위해 건물 외곽 사각형의 75%로 근사한 추정치다.
